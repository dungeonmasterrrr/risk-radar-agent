# 同花顺热榜

热度数据来自扶摇[同花顺热榜接口](https://fuyao.aicubes.cn/docs/api-reference/hot-list-data/)，不是自定义0–100评分。原始热度值只展示，禁止作为规则数值阈值。

## 数据与触发

每次按day（24小时榜）或hour（小时榜）请求GET /api/a-share/special-data/hot-stock-list，limit=100。展示排名、原始热度字符串、排名变化和趋势，保留来源时间、请求ID、周期、请求URL和榜单覆盖范围。原始热度不转成Number，避免大整数丢失精度。

- 上榜：当前在返回前100名中。
- 排名：进入前N名，N为1–100的整数。
- 排名变化：在前100名内，来源rank_change显示上升或下降至少N位。正数为上升、负数为下降，缺失不替代成0。变化参考使用上游口径，不宣称相对本系统上一次检查或上一个小时。
- 趋势：在前100名内，来源rank_trend为up/down/flat。unknown不作为触发趋势。

单条条件例子：`{type:"heat",mode:"rank",period:"day",topN:50}`。热榜可与价格、公告、日历组合；fuyao来源负责价格与热榜，ifind来源组合时公告／价格来自iFinD，热榜和交易日历实际来自扶摇，执行证据分别标明来源。

## 边界

只支持A股股票。指数、ETF、港美股不能使用此热股榜。重复代码或排名、乱序、错误标的格式拒绝采用；缺口只按从第1名起的连续覆盖判断。目标不在榜内且覆盖不足N名时，结果为unknown，不能断言未进入前N名。完整前100名未找到时可以判断对应上榜条件未满足，但不代表没有关注度。

新鲜度使用data.timestamp，而非抓取时间。过期、未来异常时间、排名变化与趋势相互冲突时无法判断。原始热度字段缺失只影响展示，不改变可验证的排名条件。

用户修改后的规则需确认新版本。旧`heat + op/value`规则保留历史；执行显示旧数值条件已停用，不再计算数值比较，也不会自动迁移为其他意思。编辑时明确选择新触发方式并确认才恢复。

上榜与持续趋势按既有命中周期去重：条件持续满足时不因原始热度值变化而重复通知；条件恢复后重新满足，仍受冷却限制。

## 使用与验证

运行与数据 → 同花顺热榜：查看两种榜单与四字段、按名称或代码筛选。

创建监控 → 同花顺热榜：选择上榜、前N名、排名变化或趋势。试算草案和执行记录均显示四字段。示例：“招商银行进入同花顺热榜前50名时提醒，使用扶摇”。“茅台热度高于80”会请求改写，不会转换成其他条件。

24小时榜是榜单周期，不是检查间隔。当前云端后台仍每小时扫描到期任务；分钟级执行需要常驻调度器。

2026-10-26已用真实密钥取到day/hour各100条完整榜单。单元测试覆盖四种触发方式、边界、原始热度不影响触发、部分覆盖、来源异常、旧规则迁移、组合来源及后台去重。公开数据验证与截图保留于本地outputs目录，不含密钥。
