# AI 使用与验证记录

记录日期：2026-10-26（Asia/Shanghai）。

## 开发过程中的 AI

本项目由 Codex 根据原题及用户确认的大纲完成需求拆解、设计、代码、测试和文档。未使用子代理。AI 提供实现建议后，使用自动化测试、类型检查、真实 HTTP 请求及 Edge 浏览器操作核验，而不把生成代码本身视为正确性证据。

关键决策与校验：

| 决策 | 验证 |
|---|---|
| AI 编译草案，确定性引擎执行 | Agent 测试检查输出校验；引擎测试固定输入、时钟和结果 |
| 缺少条件先澄清 | 模糊、多标的、不支持指标和混合逻辑用例 |
| 数据失败返回未知 | 过期、冲突、字段缺失、超时与来源缺失用例 |
| 用数据库租约与事务避免重复 | 并发领取、过期租约接管、旧执行者提交阻断用例 |
| 关闭浏览器仍执行 | 浏览器关闭后，独立 Node 进程调用后台并回读持久化记录 |

## 产品中的模型

服务端支持 OpenAI Responses API，使用 JSON Schema 结构化输出、`store=false` 和超时约束。输出再次经过本地规则校验，用户必须检查并确认。模型名和 key 从服务端环境读取，无默认真实模型调用与费用。

当前未配置真实模型凭据，因此真实模型调用、模型准确率、费用、延迟及账户可用性均未验证。自动测试使用模拟响应验证成功、无效规则、错误结构、接口失败与降级；这些测试不等同于真实模型效果评估。

参考官方文档：[Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[Responses create](https://developers.openai.com/api/reference/resources/responses/methods/create)。

## 已发现并修正的问题

1. 默认规则引用共享标的对象：负向测试发现修改会影响白名单，已改为复制标的对象。
2. 日历标准化为带毫秒 UTC 后再次校验失败：增加格式支持和重复校验测试。
3. 不存在的日期被 JavaScript 自动归一化：增加日期与时刻校验。
4. 浏览器版本测试在异步刷新完成前断言：改为等待新版记录出现。
5. 截图文件 URL 在 Windows 中文路径下未解码：改用 fileURLToPath。
6. 批量任务串行取数可能使调度请求过长：改为每轮最多 12 个、并发 4 个。
7. 未支持的附加指标可能被本地解析器忽略：增加明确拦截并请求澄清。

## 后续真实模型验收

配置凭据后，用价格、公告、日历、组合、歧义和恶意指令样例进行真实调用；逐项核对标的、阈值、单位、逻辑和澄清行为。真实服务结果、模型版本、调用日期应追加记录。不要将 key、完整私人输入或敏感上游响应纳入交付材料。
